description: Coverage vs the official Open API

**tossctl covers 100% of the official Toss Open API's read & trade scope — and goes beyond.**
Register an official key and the features it supports are **actually routed through OAuth**;
the rest go through WTS. See the [Hybrid guide](/docs/guide/hybrid-openapi) for setup.

- ✅ supported · ❌ not supported · 🔸 partial
- `Official API` column = coverage per public docs; with an official key, ✅ rows are routed via OAuth
- Rows where official is ❌ = tossctl-only (always via WTS)

## Product domain ≠ access channel

Securities, Banking, and MyData are product domains. Official Open API, WTS,
and mobile are access channels. WTS is the **Toss Securities Web Trading System**,
not a web app for general Toss Banking.

| Product domain | Access channel | Current support |
|---|---|---|
| Toss Securities | official, WTS, Securities mobile surface inside Toss | official + WTS |
| General Banking | general Toss mobile API (no corresponding WTS) | unsupported — separate mobile auth required |
| MyData cards/spending | general Toss mobile API | partially confirmed statically; unsupported |
| System | login, Open API IP, change monitoring | supported |

Despite its legacy name, `banking status` is the funding connection for
Securities stock accumulation, so it is `securities + wts`, not general Banking. Its automated-order
funding and trade-purpose MyData-account flags are also narrow Securities workflow states, not access
to general Banking or MyData records.

The absence of a web UI is not itself a reason an API is unsupported. A WTS contract can be
called without a UI once its current web-session contract is verified. General Banking/MyData
is unsupported because the main-app session, app/device headers, and request/response cipher
connector are not implemented—not because those APIs do not exist.

## `openapi` commands

| Command | Description |
|--------|------|
| `tossctl init` | Onboarding wizard — step-by-step session, official key, and trading setup |
| `tossctl openapi login` | Register your key (env vars `TOSSCTL_OPENAPI_KEY`/`TOSSCTL_OPENAPI_SECRET` or flags) |
| `tossctl openapi status` | Diagnose key · token · allowed IPs · routing state |
| `tossctl openapi test` | Validate connectivity with a real API call |
| `tossctl openapi ip list` | List allowed IPs (WTS session required) |
| `tossctl openapi ip replace-current` | Preview/confirm replacement with the current public IP |
| `tossctl openapi logout` | Delete the credentials file |

Use the global `--backend auto|wts|openapi` flag to override routing per request.

## Trading

| Feature | Command | Official API | tossctl |
|------|------|:--:|:--:|
| Buy/sell orders | `order place` | ✅ | ✅ |
| Cancel / amend | `order cancel`, `order amend` | ✅ | ✅ |
| dry-run preview | `order preview` | ❌ | ✅ |
| Fractional orders (US, amount/qty) | `order place --fractional` | ✅ | ✅ |
| Fractional orders — KRW settlement | `order place --fractional --currency-mode KRW` | ❌ | ✅ |
| Real-time push (SSE) | `push listen` | ❌ | ✅ |

<Callout type="info" title="Fractional sell (beta)">
  Implements the **US market fractional-quantity SELL** added in official Open API 1.1.5 (`order place --fractional --side sell --qty 0.5`, up to 6 decimals). Contract-tested, but **not yet live-verified** — run `order preview` before any live trade. Fractional buy remains amount-based (`--amount`).
</Callout>

## Verification basis

The `Official API` column is verified against a specific version of the
[official Open API docs](https://developers.tossinvest.com/docs). The verified version and
last-checked date are recorded in
[`.openapi-snapshot.json`](https://github.com/JungHoonGhae/tossinvest-cli/blob/main/docs/migration/.openapi-snapshot.json);
the full spec is mirrored daily and changes are auto-detected.

The full WTS web API catalog (implemented / next candidate / intentionally excluded) is
continuously tracked in
[`wts-endpoints.json`](https://github.com/JungHoonGhae/tossinvest-cli/blob/main/docs/reverse-engineering/wts-endpoints.json).
