# 수동 의도 확인과 자동화 위임을 분리한다

수동 변경은 미리보기로 고정한 의도에 대한 확인을 사용한다. 서버 상태까지 결합하는
`state_confirmation`과 주문 의도만 결합하는 `intent_confirmation`을 구분하고,
실계좌 자동투자는 대상·행동·금액 한도·유효기간·킬스위치를 가진 별도 `bounded_mandate`로만
허용한다. 전역 bypass 플래그는 두 승인 방식을 구분하지 못하고 서버 동의나 계좌 자격까지
우회하는 것처럼 보이므로 사용하지 않는다. 환전 확인처럼 사용자가 미리 자동 수락한 서버
동의는 위임의 명시적 scope로 모델링하며, 토스 서버가 요구하는 인증·자격 자체는 어느 로컬
위임으로도 우회하지 않는다.

`state_confirmation`도 토큰이 분산 환경에서 한 번만 소비된다는 뜻은 아니다. 서버
idempotency key나 조건부 쓰기 계약이 확인되지 않은 WTS 설정
변경은 같은 preview를 여러 프로세스에서 동시에 실행하면 안 된다. 향후 `bounded_mandate`는
서버 또는 영속 원장의 중복 제출 방지까지 포함해야 한다.

`intent_confirmation` 주문 토큰은 만료되지 않는 결정적 값이며 같은 의도를 다시 제출할 수
있다. 이는 실수 방지용 확인이지 replay 방지 장치가 아니다. 또한 승인은 전송 성공을 증명하지
않는다. 특히 현재 official 주문 operation은 HTTP 응답만
반환하며 transport error 뒤 자동 reconciliation을 수행하지 않는다. 서버가 주문을 반영한 뒤
응답만 유실됐을 수 있으므로 결과를 `unknown`으로 보고 미체결·체결 또는 조건주문 상태를
사람이 확인하기 전에는 같은 의도를 재시도하지 않는다. 이 원칙은 자동 재시도보다 우선한다.
