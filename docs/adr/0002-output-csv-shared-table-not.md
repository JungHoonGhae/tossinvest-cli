# ADR 0002 — CSV 렌더링만 공용화하고 표 렌더링은 각 writer 에 남긴다

- 상태: 채택
- 날짜: 2026-08-24
- 관련: `internal/output`

## 맥락

`internal/output` 에는 `Write*` 함수가 76개 있고 전부 같은 골격으로 보인다:

```go
switch format {
case FormatJSON:  ...
case FormatCSV:   ...
case FormatTable: ...
}
```

77개의 똑같이 생긴 `switch` 는 "이걸 하나로 합치자" 는 제안을 부른다. 실제로
아키텍처 리뷰에서 그 제안이 나왔고, "각 writer 는 무엇을 보여줄지만 선언하고
포맷 분기는 한 모듈이 소유한다" 는 그림까지 그렸다.

**측정해 보니 절반만 맞았다.**

| 분기 | 균일한가 | 근거 |
|---|---|---|
| JSON | 예 | 77곳 중 75곳이 `return writeJSON(w, x)` 한 줄 |
| CSV | 예 | 73곳 중 47곳이 "헤더 + 단일 루프", 나머지도 대부분 같은 골격 |
| Table | **아니오** | 76곳 중 **50곳**이 `renderTable` 외에 `Fprint` 로 산문을 함께 찍는다 |

표 분기가 찍는 산문은 장식이 아니라 의미다 — 빈 상태 안내("발동 중인
서킷브레이커가 없습니다"), 합계 줄, 누락 종목 경고, 섹션 헤더. 3곳은
`renderTableColored` 로 행마다 색을 다르게 준다.

첫 측정에서는 CSV 분기 50개가 "조건 분기 포함" 으로 잡혀 CSV 도 균일하지 않은
것처럼 보였다. 그 50개는 전부 `if err := cw.Write(...); err != nil` 이라는
**에러 검사**였다. 분류를 고치자 결론이 뒤집혔다. 이 표의 숫자는 에러 검사를
제외하고 다시 센 값이다.

## 결정

**CSV 만 `writeCSV(w, header, rows)` 로 공용화한다. 표 분기는 각 writer 가
계속 직접 렌더링한다.**

JSON 은 이미 `writeJSON` 한 줄이라 더 줄일 것이 없다.

## 이유

표까지 밀어넣으면 seam 이 이렇게 된다:

```go
render(w, format, v, csvHeader, csvRows, tableHeader, tableRows,
       preamble, epilogue, rowColors)
```

파라미터가 9개다. 이건 깊은 모듈이 아니라 **더 얕은** 모듈이다 — 인터페이스가
구현보다 복잡해진다. 50곳의 산문을 훅으로 받으려는 순간 그 훅들이 인터페이스의
대부분을 차지한다.

deletion test 도 갈린다:

- `writeCSV` 를 지우면 → 40여 곳에 같은 8줄(NewWriter · 헤더 · 루프 · Flush ·
  Error)이 되살아난다. 복잡도가 **모인다**. 통과.
- 가상의 `render` 를 지우면 → 표 산문이 원래 있던 자리로 돌아갈 뿐이다. 복잡도가
  **옮겨갈** 뿐이다. 탈락.

`writeCSV` 가 실제로 사는 이유가 하나 더 있다: `csv.Writer` 는 버퍼링하고
`Flush()` 는 실패를 돌려주지 않는다 — `Error()` 가 돌려준다. 40여 곳이 각자
기억해야 했던 규칙이고, 한 곳이라도 빠뜨리면 출력이 **조용히 잘린 채 성공으로
보고**된다. 이제 한 곳에서 강제된다(`TestWriteCSVSurfacesFlushFailure`).

## 결과

- 42곳을 이관했다. `internal/output` 순 `-238`줄.
- `csv.NewWriter` 직접 사용이 31곳 남는다. 중첩 루프, 루프 밖 추가 Write, 조건부
  Write 처럼 표준형이 아닌 것들이다. **이건 미완의 이관이 아니라 경계다.**
- 새 조회를 붙일 때 CSV 분기는 `rows` 를 만들어 `writeCSV` 를 부르면 끝이고,
  표 분기는 그 조회에 맞는 산문을 자유롭게 쓴다.
- 이관이 동작을 바꾸지 않았는지 이관 전/후 바이너리의 CSV 출력을 28개 커맨드로
  대조해 확인했다. 차이는 전부 라이브 데이터 변동(거래량·호가 잔량·서버가
  순서를 보장하지 않는 markets 필드)이었다.

## 재검토 조건

표 분기의 산문이 몇 가지 정형(빈 상태 · 합계 · 경고)으로 수렴한다면, 그 정형을
값으로 선언하는 방향은 다시 볼 만하다. 지금은 50곳이 제각각이라 정형이 없다.
