## 신규 API와 응답 계약

`GET /api/v1/rankings/investor-trading` (`getInvestorTradingRankings`)은 국내 종목(ETF 포함)의 외국인·기관·개인별 순매수·순매도 상위 목록을 함께 제공한다. 선택적 정수 쿼리 `count`는 기본 100, 허용 범위 1~100이며 투자자별 각 목록에 따로 적용된다. 실제 항목 수는 요청보다 적을 수 있다. 인증은 `oauth2ClientCredentials`, 호출 제한 그룹은 `RANKING`이다.

추가 스키마는 다음과 같다.

| 스키마 | 계약 |
| --- | --- |
| `InvestorTradingRankingResponse` | 필수 `foreigner`, `institution`, `individual` 객체. 각 참조는 `allOf`로 감싸져 있다. |
| `InvestorNetTradingRanking` | 필수 `rankedAt`(nullable date-time), `netBuyRankings`, `netSellRankings`. 데이터 미제공 시 시각이 null이고 목록이 빌 수 있다. |
| `NetBuyRankingItem` | 필수 `rank`, `symbol`, `currency`, `netBuyAmount`. |
| `NetSellRankingItem` | 필수 `rank`, `symbol`, `currency`, `netSellAmount`. |

거래액은 KRX·NXT 통합 기준의 양수 KRW 정수이며 JSON에서는 최대 길이 30의 decimal 문자열이다. 순매도 금액도 양수이므로 음수 순매수로 혼동하면 안 된다. 심볼은 영문·숫자 조합도 허용한다. 현재가·등락률은 없으며 필요한 시세는 `GET /api/v1/prices`로 별도 조회한다.

최근 영업일 데이터만 제공하며 과거 날짜를 지정할 수 없다. 투자자마다 `rankedAt`이 다를 수 있고, 장중 개인 데이터는 직전 영업일 기준이다. 외국인·기관 장중 값은 잠정치이며 NXT 반영으로 정규장 종료 후 저녁 20시경까지 바뀔 수 있다.

| 비교 대상 | 현재 구현 | 신규 API와의 관계 |

| `internal/client/marketdata.go`의 `GetInvestorRankings` | WTS `/api/v1/dashboard/wts/overview/rankings/by-investors`의 `result.rankings.*.buyStocks` 변환 | 신규 공식 응답과 직접 호환되지 않는다. 현재는 이름·시세를 포함하고 순매수만 변환한다. |
| `internal/domain/models.go`의 `InvestorRankings` 계열 | 투자자별 `based_at`, `stocks`, float64 순매수 금액 등 | 순매도 목록·통화·nullable 기준 시각·최대 30자리 금액 보존을 검토해야 한다. |

기존 `investor_rankings`에는 WTS `investor-rankings` probe가 등록되어 있으나 신규 공식 endpoint에 대한 등록은 없다. `size` 기본값은 레지스트리 설명상 20이지만 실제 `GetInvestorRankings`의 0 이하 처리값은 10이다. 공식 API의 기본 100으로 전환할 때는 기존 동작과 명시적으로 조율해야 한다.

삭제·기존 계약 변경이 없으므로 이번 스냅샷으로 직접 깨지는 기존 구현은 식별되지 않았다. 위 WTS 클라이언트·도메인·레지스트리는 향후 공식 API 통합 시 변경 영향 대상이다.

## 분류

**(b) feature candidate — 공식 투자자별 순매수·순매도 랭킹 지원 후보.**

현재 미지원인 공식 경로가 추가됐으므로 no-op이 아니다. 기존 경로·스키마가 유지되는 추가형 변경이어서 이번 커밋 자체를 breaking risk로 분류하지 않는다. 다만 WTS 구현을 단순 교체하면 순매도 누락, 이름·시세 누락, 시각 null 손실, 금액 정밀도 손실 등 호환성 문제가 생길 수 있다.

## 권장 후속 조치

1. 공식 클라이언트에 전용 응답 모델과 조회 메서드를 추가하고 `count` 범위를 검증한다. 금액 문자열의 정밀도와 투자자별 nullable `rankedAt`, 양방향 목록을 보존한다.
2. 공유 `internal/ops/`에 공식 읽기 오퍼레이션과 해당 endpoint의 `ProbeSpec`을 등록한다. 기존 `investor_rankings`의 공식 우선·WTS fallback 전환 여부는 출력 계약과 기본 조회 수를 비교한 뒤 결정한다. 이름·시세가 필요하면 별도 보강 방식을 설계한다.
3. 로컬 fixture 테스트로 count 경계, 영숫자 심볼, 큰 금액, 양수 순매도 금액, 빈 배열·null 시각, 투자자별 서로 다른 기준 시각을 검증한다. 기존 WTS 출력 계약도 회귀 검증한다.
4. 구현 전까지 기존 경로를 유지한다. 이번 분석에서는 코드 수정이나 실제 API 호출을 수행하지 않았다.

## 검증 방법과 한계

`tools/openapi_diff.py --rev 373acb1e928992eb7c843904e0b29de4874c5050`을 실행하고 신규 경로 및 4개 스키마의 실제 JSON 계약을 확인했다. 최종 미분류 변경은 0건이다. 원시 텍스트 diff는 사용하지 않았다.

분석용 부분 복제에 부모 스냅샷 객체가 없어 첫 실행은 실패했다. 이때 Git의 자동 promisor fetch가 GitHub 접근을 시도했지만 DNS 실패로 연결되지 않았다. 이후 `GIT_NO_LAZY_FETCH=1`로 자동 가져오기를 차단하고, 동일 프로젝트의 로컬 저장소 객체를 `GIT_ALTERNATE_OBJECT_DIRECTORIES`로 읽기 전용 참조하여 같은 명령을 성공시켰다. 저장소 설정과 객체 파일은 변경하지 않았다. 분석은 로컬 스냅샷·소스에 한정되며 실서비스 응답은 검증하지 않았다. 실제 계좌 데이터는 포함하지 않았다.

## 실행 결과 — 2026-10-31

- 구현: `official.InvestorTradingRankings`(`count` 1~100 사전 검증), `hybrid` 패스스루(official-only), `market investor-rankings`, ops `investor_trading_rankings`. 안정 오퍼레이션 125 → **126**.
- **노출 방식 결정**: 기존 `market investors` 에 합치지 않고 새 커맨드로 분리했다. WTS 는 이름·시세가 있고 순매도가 없으며, 공식은 그 반대라 서로 대체할 수 없다. 2026-10-11 섹터와 같은 판단이고 사용자가 뒤집을 수 있다.
- 기본 `count` 는 스펙의 100 대신 **10**. 목록 6개 × 100행이면 터미널과 MCP 결과 한도를 넘는다. `0` 은 10으로 처리한다.
- 금액은 위 권장과 달리 문자열로 보존하지 않고 기존 어댑터처럼 `float64` 로 둔다. 스펙의 최대 길이 30은 공통 decimal 제약이고, 하루 시장 금액은 `float64` 정확 범위(9천조 원)를 넘지 않는다.
- `rankedAt` 은 `*string` 으로 들고 가 null 과 빈 값을 구분한다. 순매도 금액은 양수 그대로이고 `net_sell` 목록이 방향을 나타낸다.
- probe 는 추가하지 않았다. 공식 읽기 오퍼레이션에는 probe 를 두지 않는 것이 현재 패턴이다.
- 위 "`size` 기본값 20" 은 실제 동작 10 이 맞고 설명이 틀렸다. 설명을 10 으로 고쳤다.
- **함정**: 오퍼레이션 하나를 더하자 MCP 전체 목록이 30 038 바이트로 한도를 넘었다. `backend` 필드와 중복되는 설명 끝 ` WTS-only.` 64건을 지웠다(64건 모두 `backend: wts` 확인). 다음 추가 때 설명을 다시 깎지 않아도 된다.
- 검증: `go test ./...`·`make lint` 통과. 계약 테스트는 httptest **더미 데이터**. 라이브 확인(공식 키, 2026-10-31 장외): 투자자별 목록 100건씩, 금액 전부 양수, 영숫자 종목코드 응답, 기관의 기준 시각이 외국인·개인과 다른 것을 확인. `count` 101 은 요청 전에 거절.
