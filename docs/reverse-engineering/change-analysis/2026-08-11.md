## 1. 변경 요약

diff 는 4개 지점, 전부 **국내/해외 공통 "종목 유니버스" 관련**이다.

| 위치 | 내용 |
|---|---|
| `components.responses.InternalErrorTradingTrend.description` | "종목 심볼 조회 중 일시적 오류" → "종목 정보 조회 중 일시적 오류" (오타/워딩 수정, cosmetic) |
| `components.schemas.ListedStock` | **신규 스키마** — `symbol`/`name`/`securityType`/`isCommonShare`/`isinCode` 5개 필드, 전부 required |
| `paths./api/v1/stocks` (GET, `getStocks`) | description 에 `/api/v1/stocks/all` 로의 상호참조 문장 추가(cosmetic) + 응답 예시에서 KODEX 200(ETF) 항목의 `englishName` 예시값 제거 |
| `paths./api/v1/stocks/all` (GET, `listStocks`) | **신규 엔드포인트** |

기존 `StockInfo` 스키마(`getStocks` 가 쓰는 것)는 필드 구조·required 목록 변경 없음 —
`englishName` 은 여전히 required string 이다. 예시값 제거는 문서 정합성 수정으로 보이며
스키마 자체의 breaking 변경은 아니다.

### 신규 엔드포인트: `GET /api/v1/stocks/all` (`listStocks`)

- **용도**: 마켓(거래소)별 **전체 종목 목록**(유니버스) 조회. `GET /api/v1/stocks` 가
  이미 아는 `symbols` 를 다건 상세 조회하는 것과 달리, 이 엔드포인트는 애초에 "어떤 심볼이
  존재하는가"를 알려준다 — 즉 스크리닝/유니버스 구성의 진입점.
- **파라미터**: `market`(필수, enum: KOSPI/KOSDAQ/NYSE/NASDAQ/AMEX/KR_ETC/US_ETC) ·
  `status`(옵션, 기본 ACTIVE) · `securityType`(옵션) · `commonShare`(옵션, bool).
- **응답**: `ListedStock[]` — `symbol` 오름차순, 페이지네이션 없음(전량 반환).
  스펙 설명상 마켓당 최대 수천 건(예: NASDAQ 약 2,800건, gzip ~30KB), 일 배치 갱신이라
  하루 1회 캐싱 권장.
- **Rate Limits Group**: `STOCK_ALL` (기존 `STOCK` 과 별도 그룹 — 별도 레이트리밋 정책).
- **에러**: 400(`invalid-request`, 잘못된 market) · 401 · 403 · 429 · 500(`InternalErrorStock` 재사용).
- **응답 필드가 `StockInfo` 의 부분집합**: `ListedStock` 에는 `market`/`currency`/
  `status`/`englishName`/`sharesOutstanding` 등이 없다. 스펙이 명시적으로 "여기서 얻은
  `symbol` 로 `GET /api/v1/stocks` 를 호출해 상세를 채우라"고 안내한다 — 즉 2단계 조회
  (유니버스 나열 → 상세 배치조회)를 의도한 설계.

## 2. tossctl 커버리지 대조

| 기능 | tossctl 현황 | 판정 |
|---|---|---|
| 마켓별 전체 종목 나열(`listStocks`) | 없음. `internal/official/stock_reads.go` 의 `Stocks()` 는 이미 아는 `symbols` 를 다건 조회할 뿐, 심볼을 모를 때 나열할 방법이 없다 | **신규** |
| `quote get`/`quote batch` | 사용자가 심볼을 먼저 알아야 동작 — 이번 API 가 그 전제를 채워줄 수 있는 상류(upstream) 기능 | 영향 없음(그대로 유지) |
| `internal/mcp` 오퍼레이션 카탈로그 | `stocks` ID 로 `getStocks` 만 등록, `listStocks` 상당 오퍼레이션 없음 | **신규 등록 후보** |
| CLI 커맨드 표면(`cmd/tossctl/quote.go`) | `get`/`batch`/`chart`/`trades`/`limits`/`warnings`/`flows`/`orderbook`/`sellable`/
`commission`/`crypto`/`reasoning`/`signals`/`options`/`supply` 15개 서브커맨드 — "심볼을
이미 아는 상태"를 전제로 한 것들뿐, 종목 목록/스크리너 성격의 커맨드가 없다 | **공백 확인** |

기존 `getStocks`(`/api/v1/stocks`) 코드 경로(`internal/official/stock_reads.go`,
`apiStockInfo`/`adaptStocks`)는 스키마·엔드포인트 모두 무변경이므로 영향 없음.

## 3. 분류

**(b) 신규 기능 후보.** breaking 변경 없음 — 삭제된 경로/스키마 없고, 기존 스키마의
required 필드·타입도 그대로다. 버전 번호도 그대로라 공식 쪽에서도 이번 갱신을 "no-op
급 문서 수정 + 신규 엔드포인트 추가"로 취급하는 것으로 보인다.

## 4. 권장 후속 조치

1. `internal/official/stock_reads.go` 에 `ListStocks(ctx, market, status, securityType,
   commonShare)` 추가 — `apiStockInfo` 와 별개로 `ListedStock` 5필드짜리 얇은 구조체를
   새로 둔다(필드 집합이 다르므로 재사용하지 않는다).
2. 노출 방식 결정 필요: `quote` 하위에 심볼을 몰라도 되는 성격의 커맨드가 지금 하나도
   없다. `quote list --market KOSPI [--status] [--type] [--common-share]` 형태를 새로
   만들지, `quote` 밖에(예: 최상위 `stocks list`) 둘지는 UX 판단 — 여기서 정하지 않는다.
3. `internal/ops/read_operations.go` 에 오퍼레이션 등록(`ID: "stocks_all"` 등), MCP 카탈로그도
   동반 갱신.
4. 일 배치 데이터라는 스펙 설명을 반영해 로컬 캐싱(TTL ~1일) 여부를 설계에 포함할 것 —
   실계좌/라이브 호출 테스트는 이번 스텝에서 수행하지 않았다(레포 파일 분석만).
