## 1. 공식 Open API — `timeInForce` : 국내(KR) 주식 시가단일가(OPG) 주문 정식 지원

`tools/openapi_diff.py` 결과, 신규/삭제된 경로·스키마는 없고 필드 설명(description) 변경만 발생했다.
`[미분류 변경]` 절도 같은 필드의 부수 변경(enum 배열 값 추가)이라 별도 조사로 확인 완료 — 미확인 잔여 없음.

1. **`Order.timeInForce` (응답 스키마) description**
   - 기존: `OPG`: 장 개시 주문 (At the Opening). **현재는 지원하지 않습니다.**
   - 변경 후: `OPG`: 장 개시 주문 (At the Opening, **국내 시가단일가**).
   - enum 값 자체(`DAY`/`CLS`/`OPG`)는 이전부터 동일 — 응답 스키마는 이미 `OPG` 를 문서화해 두었으나 "미지원" 각주만 있었음.

2. **`OrderCreateRequest.oneOf[0].properties.timeInForce` (요청 스키마, 수량 기반 주문)**
   - `enum`: `["DAY", "CLS"]` → `["DAY", "CLS", "OPG"]` (요청 바디에 `OPG` 사용 가능해짐)
   - description 에 조건 추가: *"현재 국내 주식 전용이며 `orderType` 은 `LIMIT`/`MARKET` 모두 지원합니다. 세션 시간(장전 사전접수) 외 접수는 원장에서 거절될 수 있습니다."*

즉 이번 변경은 신규 필드/엔드포인트가 아니라, 이전부터 응답 스키마에 예약되어 있던 `OPG` 값을 **요청 스키마에서도 실제로 허용**하도록 활성화한 것이다 (국내 주식, `LIMIT`/`MARKET` 공통, 장전 시간외 접수는 원장 거절 가능).

**예외 1건 — 2026-08-25 라이브 확인 완료, 결론이 뒤집혔다.**

`internal/client/trading.go` 의 `getUSDBaseExchangeRate` 는
`/api/v1/exchange/usd/base-exchange-rate` 를 **경로 파라미터 없이** 호출한다. 위 분석은
이것을 "추출기가 `[date]` 를 자르고 남긴 오탐" 으로 보고 라이브 확인을 권고했다.

확인해보니 **코드가 맞고 카탈로그가 틀렸다.** 두 경로 모두 200 이지만 서로 다른 API 다:

| 경로 | 응답 |
|---|---|
| `/api/v1/exchange/usd/base-exchange-rate` | `{rateQuoteId, buyCurrency, sellCurrency, rate, usdMidRate, baseDate}` |
| `/api/v1/exchange/usd/base-exchange-rate/{date}` | `{usdMidRate, baseDateTime}` — **`rate` 없음** |

코드는 `rate` 를 읽으므로 날짜 없는 호출이 정확하다. `{date}` 로 "고쳤다면"
`rate=0` 이 되어 `"usd base exchange rate was empty"` 로 **주문 경로가 깨졌을 것이다**.

진짜 문제는 추출기의 그림자 제거 휴리스틱이었다. 날짜 없는 경로를 `{date}` 의 잘린 형태로
오인해 카탈로그에서 지웠고, 그래서 이 문서에 "삭제됨" 으로 잡혔다. 덤으로 부르지도 않는
`{date}` 쪽이 `implemented` 로 잘못 표시돼 있었다.

`main` 에서 조치 완료(`bd4b19e`):
- 검증된 예외만 복원하는 `REAL_SHADOWS` 도입. `IMPLEMENTED` 패턴으로 자동 판정하는 안을
  먼저 시도했으나 그건 가족 접두사라 유령 8건을 과복원했다(코드가 v3 만 부르는
  `my-assets/transactions/markets` 의 v1 형태 등).
- exchange 계열 `IMPLEMENTED` 패턴을 정확 경로로 축소 — 실제 호출은
  `current-quote/for-buy` 하나뿐인데 `current-quote`·`/for-sell`·`/{date}` 까지 잡고 있었다.
- 두 경로가 별개 API 라는 사실을 override note 에 기록해 누가 코드를 "고치지" 않도록 했다.

## 3. 권장 후속 조치

1. `timeInForce=OPG` 지원 여부 결정. `orderintent.PlaceIntent` 에 `TimeInForce` 필드를 추가하고

   - 현재는 `LIMIT` 주문에서만 `TimeInForce` 를 보내므로, `OPG`+`MARKET` 조합을 지원하려면

     로직을 손봐야 한다.
   - `OPG` 는 국내 주식 전용이므로 해외(US) 심볼에 대해서는 거부하거나 무시하는 가드가 필요하다.
   - 세션 시간(장전 사전접수) 외 접수 시 원장에서 거절될 수 있다는 문서 경고를 사용자 안내
     문구에 반영할지 판단 필요.
   - **완료(2026-08-25, v0.43.0)**: `order place --time-in-force` 로 출시했다. 위에서 예측한
     세 가지를 모두 처리했다 — `LIMIT` 분기 밖에서도 `TimeInForce` 를 세팅하고, 시장별 조합
     규칙(`CLS`=미국+지정가, `OPG`=국내)을 `NormalizePlace` 에서 거절하며, 세션 시간 경고를

     `time_in_force` 를 묶었다.** 안 묶으면 `DAY` 로 미리보기해 받은 토큰으로 `OPG` 주문을
