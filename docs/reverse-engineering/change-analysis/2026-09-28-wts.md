# WTS 수집·감시 보완과 리서치 조회 확장 — 2026-09-28

공식 REST 1.2.17과 AsyncAPI 1.2.2는 저장소 스냅샷과 JSON 전체가 동일했다.
WTS는 최신 빌드 `LCgFIQwFsag3GrRgpJus7`의 86개 청크를 수집했다. 경로·호스트·메서드는
[9/21 카탈로그 PR #277](https://github.com/JungHoonGhae/tossinvest-cli/pull/277)과 같았다.
새로 관측된 경로를 서버에 새로 출시된 API로 단정하지 않는다.

## 수정과 근거

### gzip 번들 수집

공통 앱 청크는 `Content-Encoding: gzip`과 실제 gzip 본문을 반환했다. 기존 수집기는
이를 UTF-8로 바로 디코딩해 경로가 1,149개에서 6개로 급감한 것으로 판단하고 중단했다.
보호장치는 정상 작동해 기존 카탈로그를 보존했다.

수집기에 gzip 해제를 추가했다. 압축 본문·해제한 본문 각각에 기존 크기 제한을 적용하고,
총 예산에는 둘 다 포함한다. 손상된 압축·지원하지 않는 인코딩은 오류로 처리한다.
원본 호스트·리디렉션·수집량 제한은 유지한다.

### 검색·섹터 호스트 검증

`POST /api/v2/search/stocks`와 `GET /api/v1/tics/all`의 최신 선언은 `wts-api`지만,
기존 CLI는 `wts-info-api`를 사용한다. 이 차이로 PR #277의 probe/catalog 검사가 실패했다.
실제 두 호스트 모두 검색 `result.stocks`, 섹터 `result.ticsItems` 배열을 반환했고,
현재 Go probe의 스키마 검사를 통과했다. 최신 섹터 청크에도 INFO 직접 호출이 남아 있다.

이 두 경로에 한정해 검증된 호스트 쌍을 허용했다. 다른 경로나 CERT 호스트까지 허용하지
않으며, 클라이언트의 호출 호스트도 바꾸지 않았다. 핵심 스키마 호환성을 확인한 것이며
전체 응답 필드·값이 동일하다는 뜻은 아니다.

### 기존 가격 API 보존

`/api/v1/product/stock-prices`는 번들에서 사라졌지만 CLI가 사용 중이고 실제로 응답한다.
`quote-product-prices` probe를 추가해 CLI와 같은 `meta=true&productCodes=A005930`으로
조회한다. HTTP 200, 비어 있지 않은 배열, `productCode`·`close`·`currency` 타입을 검증한다.
기존 runtime probe 수집 경로를 통해 번들에 없는 이 API도 카탈로그에 보존한다.

감시 보완 직후 카탈로그는 1,307개(구현 165 / 후보 450 / 제외 692)였다.
아래 신규 읽기 계약 4개를 검증·구현한 최종 상태는 구현 169 / 후보 446 / 제외 692다. 저장소의 9/14 기준으로
176개 추가·18개 미관측이며 구현 경로 삭제는 없다. PR #277에 남은 최초 관측일과 기존
override·capture 근거를 보존했다. 기본 probe는 가격 조회와 새 기능을 포함해 91개, paper 옵트인 시 95개다.

## 검증

- `make build`, `make test`, `make lint` 통과.
- Python 도구 테스트 126개가 `PYTHONHASHSEED=0`과 `1`에서 각각 통과. 압축/비압축 결과 일치, 손상·잘림·용량 제한,
  제한된 호스트 허용, 번들에서 사라진 가격 계약의 보존을 포함한다.
- 수정한 수집기로 실제 최신 웹 번들 수집 성공.
- 검색·섹터 각각 2개 호스트와 가격 조회 1개, 총 5개 공개 읽기 요청에서
  HTTP 200 및 실제 Go probe의 스키마 검사 통과.

- 문서 MDX 생성(`pnpm exec fumadocs-mdx`) 통과.
- 사용자 재로그인 뒤 `auth status`의 `valid=true` 확인. 최종 실서비스 감시는
  **95 passed, 0 failed, 0 skipped**(안정 표면 91개 + 기존 paper 옵트인 4개)였다.
- MCP 기본 목록 120개가 응답 크기 한도 내에서 생략 없이 반환되는 회귀 테스트 통과.
  새로운 설명을 추가하면서 초과한 크기는 기존 중복 문구를 줄여 해결했다.
- 폴더 뉴스 probe는 조회 대상 폴더를 선행 목록에서 얻지만 응답은 뉴스 목록이다.
  공통 runner가 모든 폴더 범위 응답에 `result.watchlists`를 요구하던 문제를 수정했다.
  폴더 상세 probe의 요청 ID 일치 검사와 선행 목록 실패·빈 목록 처리는 유지했다.

## 신규 기능과 실제 확인

| CLI | ops/MCP | 확인 결과 |
| --- | --- | --- |
| `market signal KGG01P --type index` | `ai_signal_detail`의 `product_type=index` | 지수 설명과 출처 뉴스 5건. 제공되지 않은 약관 메타데이터는 `terms:null` |
| `market earnings transcript <event-id>` | `earning_call_transcript` | 지난 주요 발표의 158개 문단. 소수 초 시간·원문·번역·요약 보존. 예정 발표는 `available:false`, 빈 문단 |
| `market earnings report <event-id>` | `earning_call_report` | 지난 발표는 분석·관전 포인트·출처 ID. 예정 발표는 분석 null, 관전 포인트는 제공 |
| `watchlist news <folder-id>` | `watchlist_news` | 기존 폴더 두 개에서 서로 다른 결과. 선택한 폴더의 실제 CLI 출력도 확인 |

종목 AI 상세의 신규 선언은 기존 `market signal`과 기능이 겹쳐 별도 명령을 만들지 않았다.
지수 경로만 확장했고 기존 종목/ETF 조회는 유지했다. 명시적인 `result:null`과 응답 wrapper
누락을 구분하며, 약관 상태가 없을 때 false로 만들어 내지 않는다.

실적 본문은 명시적 빈 배열과 잘못된 응답을 구분하고 event ID·문단 ID·시간 범위를 검사한다.
번역/요약 null은 그대로 출력하며 미생성·미제공 사유를 추측하지 않는다. 보고서의 분석과
관전 포인트는 각각 null일 수 있다. 출처의 ID와 기관·작성 시각을 보존하고 URL을 만들지 않는다.

폴더 뉴스는 폴더 상세에서 존재를 확인한 뒤 정확한 `watchlistId`를 보낸다. 없는 폴더를
전체 관심종목 뉴스로 대체하지 않는다. 서버가 제공하는 추천 뉴스 한 페이지이며, 폴더 종목의
모든 뉴스를 빠짐없이 제공하는 기능은 아니다. 관련 종목 추천(`/recommend/tics`)은 응답은
확인했지만 이번 CLI 범위에 포함하지 않았다.

모든 새 조회는 table/json/csv를 지원한다. 긴 본문은 MCP 크기 한도로 잘릴 수 있으므로
fields 선택이나 CLI로 전체를 읽는다. 기본 명령 목록과 한·영 레퍼런스를 갱신했다.

기존 `internal/official/candle_reads.go` 수정은 보존했다. 로컬 실행 파일은 `bin/tossctl`로
빌드했으며 전역 설치 바이너리 교체·커밋·배포·주문·설정 변경은 수행하지 않았다.
