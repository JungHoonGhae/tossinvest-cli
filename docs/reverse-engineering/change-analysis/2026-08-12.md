# API 변경 분석 — 2026-08-12

> **breaking-risk** — 경로는 그대로인데 **값의 단위가 바뀌었다.** 타입도 개수도 안 변해서
> 스키마 차분만 보면 no-op 으로 보인다.

## 0. 스코프

공식 Open API spec 스냅샷 갱신(`6386f11`)만 대상. `info.version` **1.2.13 → 1.2.14**.
경로·스키마 **추가·삭제 0건**.

## 1. 변경 요약

`components.schemas.Commission.properties.commissionRate` 한 곳과 그 필드를 쓰는 응답
예시들뿐이다.

| | 1.2.13 | 1.2.14 |
|---|---|---|
| description | 수수료율 (%). 예: 0.015는 0.015% | 매매 수수료율 (**소수 비율**). 예: `0.00015` = 0.015% |
| example | `"0.015"` | `"0.00015"` |
| 응답 예시 | `0.015` / `0.1` / `0.25` | `0.00015` / `0.001` / `0.0025` |

**같은 요율을 100배 다르게 쓴다.** 필드명·타입은 그대로라 diff 규모는 작지만 의미가
뒤집혔다.

## 2. tossctl 커버리지 대조

`internal/official/commissions_reads.go` → `quote commission`.

출력은 `formatPercent`(×100)를 태운다. 즉 **코드는 원래부터 "소수 비율" 을 가정하고
있었다.**

| | 코드 가정 | 구 spec | 신 spec |
|---|---|---|---|
| 0.015 입력 | 1.5% 로 표시 | 0.015% 여야 함 → **100배 과다** | — |
| 0.00015 입력 | 0.015% 로 표시 | — | 0.015% ✅ |

구 spec 이 맞았다면 `quote commission` 은 **줄곧 100배로 표시하고 있었다.** 파일 주석도
`"0.015" (1.5%)` 라고 적어 구 spec 과 어긋나 있었다 — 코드와 문서가 같은 오해를 공유했고,
이번 spec 수정이 그 오해 쪽으로 정렬됐다.

### 확정하지 못한 것

**라이브 대조를 못 했다.** `/api/v1/commissions` 가 `x-tossinvest-account` 헤더를 요구하는데
현재 이 환경에서 채워지지 않는다(`account-header-required` 400). 서버가 실제로 언제부터
어느 표현을 주는지는 미관측이다.

따라서 이번 변경이 **(a) 서버 동작 변경**인지 **(b) 문서가 서버에 맞게 정정된 것**인지
가르지 못했다. (b) 라면 `quote commission` 은 계속 정확했던 것이고, (a) 라면 오늘부로
정확해진 것이다. 어느 쪽이든 **지금 코드가 신 spec 과 일치**하므로 표시 로직은 건드리지
않는다.

## 3. 분류

**(c) breaking-risk 이지만 코드 변경 불필요.** 단위 규약이 코드 가정과 일치한다.

위험은 남아 있다 — 스케일은 뒤집혀도 에러가 안 난다. 숫자만 100배 달라진다.

### 형제 필드와 섞지 말 것

이 레포에는 규약이 반대인 필드가 있다. WTS `account commission` 의 `RatePercent` 는
**이미 퍼센트**라 `formatFloat + "%"` 로 낸다(`internal/client/commission_schedule.go`).
공식 `quote commission` 은 소수 비율이라 `formatPercent`(×100)를 태운다. 양쪽 주석에
서로를 가리키게 적어뒀다.

## 6. 같은 날 두 번째 커밋 — `7628bd2`

`createConditionalOrder` 의 **오퍼레이션 설명**에 발동 세션 문단이 추가됐다.
`operationId`·파라미터·스키마는 그대로다.

```
+ **발동 세션**: 조건 감시·발동 세션은 시장에 따라 다릅니다.
+ - 국내 주식: KRX 정규장에서만 발동됩니다.
+ - 해외 주식: 장 구분과 상관없이, 거래 가능한 모든 시간대에 발동됩니다.
```

### no-op 이 아니다

코드 조치는 불필요하지만 **사용자가 겪을 규칙**이다. 국내 조건주문을 장 마감 후에
걸어두면 다음 정규장까지 감시가 시작되지 않는데, 그때 사용자는 "왜 발동을 안 하지" 로
받아들인다. `order conditional` 의 Long 도움말에 넣었다(ko/en).

### 도구의 두 번째 맹점

이번에도 집합 차분은 `+0 / -0` 이었고, 5절에서 넣은 `[필드 의미 변경]` 도 **못 잡았다** —
그건 `components.schemas` 의 properties 만 훑는데 이 변경은 오퍼레이션 레벨이다.

`[오퍼레이션 설명 변경]` 절을 추가했다. 통짜 비교는 읽을 수 없어 줄 단위로 갈라
새로 생긴 줄만 낸다.

**동작 규칙은 세 곳에 흩어져 적힌다** — 스키마 필드 description, 오퍼레이션
description, 그리고 경로 추가. 셋 다 봐야 한 바퀴다.
