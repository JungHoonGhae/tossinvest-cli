## 6. 공식 Open API spec 갱신 (`docs/migration/openapi.latest.json`, commit `b3565de`)

같은 날 별도 자동화(`docs(migration): openapi-snapshot 자동 갱신`)가 공식 spec
스냅샷을 갱신했다. 위 0~5절(WTS 카탈로그)과는 무관한 변경이라 별도 절로 남긴다.

### 6.1 변경 요약

`info.version` `1.2.5` → `1.2.9`. 실질 변경은 4가지, 전부 주문/조건주문(order,
conditional-order) 영역:

1. **호가 단위(tick size) 검증 문서화** — `ConditionRequest.orderPrice`,
   `OrderCreateRequest.price`, `OrderModifyRequest.price` 설명에 "호가 단위에
   맞지 않으면 `400 invalid-request` + 올바른 호가가 `data`에 포함" 문구가
   명시적으로 추가됨. `createConditionalOrder`/`modifyConditionalOrder` 두
   오퍼레이션의 400 응답에 신규 예시 `invalidTickSize`
   (`data: {field, tickSize, nearestPrices}`)가 추가됐다. 기존 동작의 문서
   명확화로 보이며, 신규 검증 규칙이 아니다.
2. **소수점 거래 접수 마감 시각 단축** — 소수점 수량 매도(`MARKET`+`SELL`)와
   금액 주문(`orderAmount`)의 접수 가능 시간이 "정규장 시간 전체"에서
   "정규장 시작 ~ 정규장 종료 1시간 전"으로 좁혀짐 (`createOrder` 설명,
   422 에러 메시지 갱신). 이건 문서 정리가 아니라 **서버 측 비즈니스 룰
   변경**이다.
3. **에러 응답에 `orderableHours` 필드 추가** — `amountOrderOutsideRegularHours`,
   `fractionalQuantityOutsideRegularHours` 422 에러의 `data`에 기존
   `regularHours`(정규장 시간) 옆에 `orderableHours`(실제 접수 가능 시간,
   위 1시간 단축분 반영)가 병기됨.
4. **`modifyOrder`(정정) 400 응답에서 `amountOrderOutsideRegularHours` 예시
   제거** — 정정 요청 스키마엔 애초에 `orderAmount` 필드가 없어 이 에러가
   날 수 없었다. 잘못 들어가 있던 예시를 정리한 것으로 보인다.

### 6.2 tossctl 커버리지 대조

- `createOrder`/`modifyOrder` → `internal/official/orders_write.go` 구현됨.
- `createConditionalOrder`/`modifyConditionalOrder` →
  `internal/official/conditional_writes.go` 구현됨.
- 에러 처리(`internal/official/errors.go`)는 4xx를
  `*APIError{Code, Body}`로 **원문 그대로 패스스루**하고 `data` 필드를
  구조화 파싱하지 않는다 (`ShouldFallback`이 코드 종류만 구분).
  → 에러 스키마에 `orderableHours`/`invalidTickSize` 예시가 추가돼도 클라이언트
  파싱 로직에 영향 없음.
- 정규장 종료 1시간 전 컷오프는 서버 사이드 검증이며, 코드베이스에 로컬
  시간창 검증 로직이 없다 (`internal/client/trading.go`의 "market closed"는
  에러 메시지를 사용자에게 그대로 보여주는 주석일 뿐, 별도 시간 계산 없음).
  즉 클라이언트는 그대로 요청을 보내고 서버가 422로 거부하면 메시지를
  패스스루하는 구조라 코드 변경이 필요 없다.
- README/한글 문서에 정규장 관련 접수 마감 시각을 안내하는 문구는 없음
  (grep 결과 0건) — 갱신할 사용자 대면 문서도 없다.
