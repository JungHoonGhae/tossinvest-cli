# API 변경 분석 — 2026-09-14

## 요약

**분류: (c) breaking risk — 국내 거래 세션의 의미 변경.** 대상 커밋 `3095579bff861112a34375d287c93ee3430b22fe`와 부모 `dba6cebbec743731b9a2630dc39426ec7eafbde7`의 공식 OpenAPI 스냅샷을 비교했다.

- 버전: `1.2.15 → 1.2.17`. 경로 33개, 스키마 90개로 각각 추가·삭제 0개다.
- 변경은 버전 1개, 필드 설명 6개, 오퍼레이션 설명 3개, 스키마 설명 2개로 총 12개 JSON 경로다. 요청·응답의 타입, 필수 필드, enum 변경은 없다.
- 국내 `afterMarket`이 NXT 전용에서 **KRX·NXT 애프터마켓의 합집합**으로 재정의됐다. 시작은 가장 이른 시각, 종료는 가장 늦은 시각이며 두 거래소 모두 휴장일 때만 세션이 null이다. `singlePriceAuctionEndTime`은 NXT 기준으로, NXT 애프터마켓 휴장 시 null이다.
- 국내 캘린더의 제외 범위는 “시간외종가/시간외단일가”에서 “장전/장후 시간외종가”로 바뀌었다. 공매도 비중 분모의 세션 설명도 “장전·장후 시간외종가, 애프터마켓”으로 정리됐다.
- 주문 조회 설명에서 미지원 유형의 예시인 “시간외단일가”가 빠졌다. 이것만으로 새로운 주문 유형이나 실주문 지원이 추가됐다고 단정할 수 없다.

AsyncAPI는 변경 파일 목록에 없으며 부모·대상 커밋의 blob이 모두 `cfdfff7d78438ff39d1cbea44c11e327ed514979`로 동일하다. 추가 AsyncAPI diff 대상은 없다. 위 판단은 문서 계약 비교이며 실제 서버 변경 시점이나 동작을 관측한 결과는 아니다.

## 구현·공유 레지스트리 커버리지 비교

신규 endpoint가 없으므로 신규 공식 클라이언트 구현이나 ops 등록 후보는 없다. 변경된 기존 기능은 모두 구현·등록돼 있다.

| 변경 대상 | `internal/official/` 구현 | `internal/ops/` 연결 | 영향 |
| --- | --- | --- | --- |
| `GET /api/v1/market-calendar/KR`, `IntegratedHour`, `AfterMarketSession` | `calendar_reads.go`의 `MarketCalendar`, `businessDayRaw.sessions`, `sessionRaw` | `read_operations.go`의 `market_calendar`가 국가별 경로를 호출한다. `market business-days`에도 노출된다. | 서버 시각을 그대로 전달하고 null 세션을 건너뛰므로 새로운 합집합 구간을 수용할 수 있다. 다만 `after_market`을 NXT 영업 여부로 해석하는 소비자는 틀린 판단을 할 수 있다. |

구체적인 문서 불일치는 `internal/domain/models.go`의 `TradingSession` 주석이다. `SinglePriceAuction*`를 KRX 경매 구간이라고 일괄 설명하지만, 새 계약의 애프터마켓 `singlePriceAuctionEndTime`은 **NXT 기준**이다. ops 캘린더 설명도 거래소별 의미와 합집합 규칙을 명시하지 않는다. `calendar_reads_test.go`의 `TestMarketCalendarNormalizesKR`는 정상 세션을 검증하지만, KRX만 개장하고 NXT는 휴장인 사례를 직접 검증하지 않는다.

## 분류 근거

**전체 판정은 (c) breaking risk**다. JSON 구조가 유지돼도 `afterMarket != null`의 의미가 “NXT 애프터마켓 개장”에서 “KRX 또는 NXT 애프터마켓 개장”으로 달라진다. 단일가 시각의 거래소 귀속에 관한 기존 도메인 주석도 새 계약과 충돌한다. 세션 정보에 의존하는 일정·알림·거래 가능 시간 판단에 의미상 호환성 위험이 있으므로 no-op으로 처리하지 않는다.

공매도 변경은 분모에 포함되는 세션의 설명 정비이며 단위 변경이나 계산식 변경을 입증하지 않는다. 주문 조회의 제외 예시 삭제 역시 신규 주문 기능의 근거로 삼지 않는다. 이번 커밋에는 신규 endpoint나 주문 요청 enum 변경이 없어 별도 (b) feature candidate로 제안할 구현은 없다.

## 미분류 경로 전수 검토

`python3 tools/openapi_diff.py --rev 3095579bff861112a34375d287c93ee3430b22fe`를 성공 실행했다. 원본 도구가 마지막에 출력한 미분류 2개 경로는 양쪽 JSON의 잘리지 않은 값을 읽어 다음과 같이 분류했다.

| 미분류 경로 | 전체 값 검토 결과·분류 |
| --- | --- |
| `components.schemas.AfterMarketSession.description` | “애프터마켓 세션 (NXT)”에서 “KRX·NXT 애프터마켓의 합집합(가장 이른 시작 ~ 가장 늦은 종료)”으로 변경. 위 거래 세션 의미 변경에 포함되는 breaking risk다. |
| `components.schemas.IntegratedHour.description` | 제외 범위가 장전/장후 시간외종가로 바뀌고 각 세션은 KRX·NXT 모두 휴장일 때 null이라는 규칙이 명시됐다. 세 세션이 모두 null이면 상위 `integrated`도 null이라는 규칙은 유지된다. 위 통합 세션·휴장 판정 위험에 포함한다. |

도구의 `flatten`으로 전체 스냅샷을 구조적으로 비교하고, 버전 1개 + 필드 설명 6개 + 오퍼레이션 설명 3개 + 위 스키마 설명 2개의 집합이 전체 변경 경로 12개와 정확히 같음을 메모리 내 assertion으로 검증했다. **최종 수동 검토 잔여 [미분류 변경] 없음(0건)**. 도구 자체를 수정하거나 원본 미분류 출력 2건을 숨긴 것은 아니다.

## 권장 후속 조치

1. `TradingSession` 주석과 캘린더 ops·사용자 설명에 KRX·NXT 합집합, 두 거래소 모두 휴장일 때 null, 애프터마켓 단일가 종료는 NXT 기준이라는 규칙을 반영한다. 세션 존재만으로 NXT 개장을 추론하는 소비자가 있는지 점검한다.
2. 오프라인 fixture로 KRX만 개장/NXT 휴장, NXT만 개장, 둘 다 휴장, 양쪽 개장 시 시작·종료 범위 보존을 검증한다. 세션이 존재하면서 단일가 종료가 null인 경우의 출력과 휴장 판정도 확인한다.
3. 공매도 설명을 새 세션 용어에 맞추고, 기존 비율을 그대로 보존한다. 설명 변경만을 이유로 비율에 100을 곱하거나 분모를 임의로 재계산하지 않는다.
4. 주문 조회 설명의 제외 예시를 정리하되 새 주문 유형 지원으로 확대 해석하지 않는다. 후속 공식 계약에서 지원 범위가 명확해지면 조회 fixture와 문서를 보완한다.

## 실행 범위와 제한

로컬 스냅샷과 구현·테스트 소스를 읽고 이 보고서 한 파일만 작성했다. OpenAPI raw text diff, 실서비스 API 요청, 실제 계좌 데이터 접근, 커밋·push는 수행하지 않았다. 구현 변경이 없어 테스트 스위트는 실행하지 않았고 구조적 변경 집합의 완전성을 검증했다.

최초 도구 실행과 커밋 통계 조회에서 부분 복제 저장소의 객체 누락으로 Git이 GitHub 자동 fetch를 시도했으나 DNS 오류로 실패했다. **이는 GitHub 호출 금지 조건에서 벗어난 실행상 이탈이다.** 이후 `GIT_NO_LAZY_FETCH=1`과 `protocol.allow=never`를 적용하고, `GIT_ALTERNATE_OBJECT_DIRECTORIES`로 기존 로컬 저장소 객체를 읽어 분석을 완료했다. Git 설정이나 객체 파일을 직접 변경하지 않았다.

## 후속 반영 — 2026-09-15

- `TradingSession` 주석, CLI 도움말, ops/MCP 설명과 한·영 가이드에 애프터마켓 합집합 및 NXT 단일가 종료 시각의 생략 규칙을 반영했다. 기존 소비자는 세션 이름으로 NXT 개장을 판단하지 않고 서버 시각을 출력하므로 어댑터 변경은 필요하지 않았다.
- 합성 fixture로 KRX만 개장, NXT만 개장, 양쪽 개장의 서버 구간 보존, 애프터마켓만 휴장, 종일 휴장을 검증했다. KRX만 개장할 때 세션과 영업일 판정을 유지하고 NXT 단일가 종료 필드만 JSON에서 생략하는 것도 확인했다.
- 공매도 비중 fixture를 실제 계약의 소수 비율 예시로 보완하고 원본 null·0·소수값 보존을 검증했다. 문서에는 원본 null이 tossctl JSON에서 비중 필드 생략으로 표현됨을 구분했다. 분모 재계산이나 100배 변환은 추가하지 않았다.
- 주문 조회의 제외 예시를 장전·장후 시간외종가로 정리했다. 새로운 주문 유형·엔드포인트는 추가하지 않았으므로 카탈로그 분류와 overrides 변경은 없다.
- `make test`와 `make lint`가 통과했다. 첫 전체 테스트에서는 길어진 ops 설명이 MCP 전체 목록의 크기 한도를 넘겼다. 설명을 간결하게 정리한 뒤 기존 117개 기능 전체가 생략 없이 반환되는 테스트까지 통과했다. 실서비스 API 호출은 필요하지 않아 수행하지 않았으며, 배포 서버의 의미 변경 시점을 관측했다는 뜻은 아니다.
