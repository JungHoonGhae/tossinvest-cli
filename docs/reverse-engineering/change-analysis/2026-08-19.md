# API 변경 분석 — 2026-08-19

## 0. 스코프

공식 Open API spec 스냅샷 갱신(`60f7558`)만 대상. `info.version`은 `1.2.14`에서 불변.
경로·스키마 **추가·삭제 0건**, diff 전체 59줄(문서 필드만).

## 1. 변경 요약

| 위치 | 내용 |
|---|---|
| `Order.orderedAt` example | `"2026-03-29T09:30:00+09:00"` → `"2026-03-29T09:30:00.000+09:00"` (밀리초 추가) |
| `OrderExecution.filledAt` example | 동일하게 밀리초 추가 |
| `OrderExecution.averageFilledPrice` description | "부분 체결 시 체결된 건의 평균" → "…, **미체결 시 null**" 문구 추가 |
| `externalDocs` (최상위, 신규) | 실시간 웹소켓 API(AsyncAPI 3.0) 스펙 URL 추가: `https://openapi.tossinvest.com/openapi-docs/latest/asyncapi.json` |
| `info.description` (신규) | 이 문서가 REST 스펙이며, 실시간 체결·호가·본인 주문 이벤트는 REST 가 아닌 `wss://openapi-ws.tossinvest.com/ws/v1` 웹소켓으로 제공된다고 명시 |
| `tags[Market Data].description` | "웹 소켓은 추후 지원 예정입니다" 문구를 삭제하고, 웹소켓 구독 안내(엔드포인트 + AsyncAPI 링크)로 교체 |

핵심은 필드 레벨 변경이 아니라 **문서 최상위 announcement**: 토스 공식 Open API가
웹소켓 실시간 스트리밍(AsyncAPI 3.0)을 정식으로 문서화하기 시작했다. `docs/migration/open-api.md`는
지금까지 "프로토콜: REST only (마케팅 페이지의 WebSocket 언급은 아직 spec 에 없음)"라고
적어뒀는데, 이번 갱신으로 그 전제가 깨졌다.

## 2. tossctl 커버리지 대조

- **밀리초 추가 (`orderedAt`/`filledAt`)**: `internal/official/orders_reads.go`는 두 필드 모두
  `time.Parse(time.RFC3339, ...)`로 파싱한다. Go의 RFC3339 레이아웃은 밀리초(fractional
  seconds) 유무와 무관하게 그대로 파싱되고, `OrderDate`는 문자열 앞 10글자(날짜부)만 취하므로
  영향 없음. 코드 변경 불필요.
- **`averageFilledPrice` null 명시**: `orders_reads.go:161` 주석에 이미 "nullable → parseDecimal"로
  처리한다고 적혀 있고, 실제 파싱 코드도 null을 처리한다. 문서가 기존 구현을 뒤늦게 따라온
  케이스라 코드 변경 불필요.
- **웹소켓(AsyncAPI) 신규 announcement**: 레포 전체(`internal/`)에 `websocket`/`asyncapi`/`wss://`
  참조가 REST 클라이언트 코드에는 전혀 없다 (`internal/official/*.go` 어디에도 없음). 즉
  **공식 웹소켓에 대한 구현은 0%.** 관련 문서는 두 곳뿐:
  - `docs/reverse-engineering/push-events.md` — 리버스 엔지니어링한 **비공식** 웹소켓(내부 앱 프로토콜) 문서.
  - `docs/migration/open-api.md` — "REST only" 전제로 작성된 공식 API 마이그레이션 계획서.
  이번 `externalDocs`가 가리키는 AsyncAPI 3.0 스펙 자체는 별도 문서(`asyncapi.json`)이고
  이 레포 스냅샷 대상이 아니라서, 실제 구독 스키마·한도·재연결 규칙은 이번 diff만으로는
  확인 불가.

## 3. 분류

**혼합.**

- 밀리초 example 변경, `averageFilledPrice` null 문구 — **(a) no-op.** 코드는 이미 신 spec과
  일치하게 동작한다.
- `externalDocs` / `info.description` / Market Data 태그 설명 갱신 — **(b) 신규 기능 후보.**
  공식 웹소켓 API가 (최소 문서상) 등장했다는 신호. breaking은 아니다 — 기존 REST 엔드포인트는
  경로·스키마 그대로이고, 웹소켓은 REST를 대체하는 게 아니라 폴링의 대안으로 추가되는 것.

## 4. 권장 후속 조치

1. `docs/migration/open-api.md`의 "프로토콜: REST only" 문구를 갱신 — 공식 웹소켓이 최소
   문서 차원에서는 나왔다는 사실을 반영.
2. 별도 세션에서 `asyncapi.json`(https://openapi.tossinvest.com/openapi-docs/latest/asyncapi.json)을
   가져와 구독 채널·메시지 스키마·rate limit·재연결 규칙을 리버스가 아닌 **공식 스펙 기준으로**
   검토. `push-events.md`(비공식 리버스 엔지니어링 웹소켓)와 스키마가 얼마나 겹치는지도 비교해볼
   가치가 있음 — 공식 웹소켓이 안정화되면 `push-events.md` 기반 구현을 공식 스펙으로 갈아탈 명분이
   생긴다.
3. 이 시점에는 실계좌/라이브 연결이 필요한 검증(WebSocket 핸드셰이크, 인증 방식 등)은 보류.
   문서만 읽고 판단 가능한 범위(스펙 구조, 채널 목록)까지만 다음 스텝에서 진행.
4. 코드 변경은 없음 — REST 클라이언트(`internal/official/*.go`)는 그대로 둔다.
