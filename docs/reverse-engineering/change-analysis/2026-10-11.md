# API 변경 분석 — 2026-10-11

## 요약

**분류: (b) feature candidate — 공식 섹터 API 5개 신설, 조건주문 계약 보강.** 라이브
`openapi.json`(1.2.24)과 저장소 스냅샷(1.2.17, 커밋 `3095579`)을 `tools/openapi_diff.py` 로
집합 비교했다. 스냅샷이 1.2.17 에 멈춰 있던 이유는 아래 "함정" 절에 있다.

- 버전 `1.2.17 → 1.2.24`. 경로 33 → 38 (+5 / −0), 스키마 90 → 101 (+11 / −0). **삭제 0.**
- 신규 경로 5개는 전부 `Sector` 태그(토큰만으로 호출, 계좌 무관, Rate Limits Group `SECTOR`·`SECTOR_RANKING`):
  `GET /api/v1/sectors`, `/sectors/rankings`, `/sectors/{sectorId}`, `/sectors/{sectorId}/stocks`, `/sectors/{sectorId}/etfs`.
- 필드 의미 변경 3건: `ConditionalOrderCreateRequest.expireDate`·`ConditionalOrderModifyRequest.expireDate` 에
  "오늘로부터 최대 1년" 규칙 추가, `OAuth2TokenRequest.client_id` 예시 형식 변경(`c_…` → `tsck_live_…`, 예시만).
- 오퍼레이션 설명 변경 1건: 조건주문 수정 본문이 `type`·`quantity`·`orderType`·`expireDate`·`first`(·`second`) 를
  모두 받는다고 명시. **기존 `ConditionalModifyBody` 가 이미 이 모양**이라 코드 변경 없음.
- 스펙 메타 변경 1건: `tags[Sector]` 신설. 대분류(depth 0)·중분류(1)·소분류(2) 계층, 한 종목이 여러 섹터 소속 가능.
- 미분류 39건 전수 검토(아래 절). 실질 변경은 **`ConditionalOrderCondition.orderSide` 가 required 로 추가**된 것 하나.
  나머지는 섹터 404/500 응답 컴포넌트, OAuth 400 예시 세분화(`missingClientSecret`·`missingGrantType`·`malformedCredentials`),
  PowerShell 코드 샘플, `x-tagGroups` 에 Sector 추가다.

AsyncAPI 는 1.2.2 로 라이브·저장소 해시가 같다(`176595a3…`). 실시간 스펙 변경 없음.

## 신규 경로 호출법

| 경로 | 파라미터 | 응답(핵심) | nullable |
| --- | --- | --- | --- |
| `GET /sectors` | 없음 | `sectors[]{sectorId, name, depth, parentSectorId}` depth↑·sectorId(숫자)↑ 정렬 | `parentSectorId`(depth 0) |
| `GET /sectors/rankings` | `type` TOP_GAINERS\|MARKET_TRADING_AMOUNT, `marketCountry` KR\|US, `duration` 1d\|1w\|1mo\|3mo\|6mo\|1y (모두 필수) | `rankings[]{rank, sectorId, name, changeRate, tradingAmount, marketCapitalization, currency}` 최대 100, depth 0·1 만 | `tradingAmount`·`marketCapitalization`. `changeRate` 는 항상 값 |
| `GET /sectors/{id}` | `marketCountry` | `{…Sector, summary, performance.changeRates[]{duration, changeRate}}` 항상 6건 1d→1y | `summary`, `changeRate`(해당 시장 구성 종목 없음) |
| `GET /sectors/{id}/stocks` | `marketCountry` | `stocks[]{symbol, name, marketCapitalization, tradingAmount, volume, currency}` 시총↓, 하위 섹터 포함, 보통주만 | 세 금액 전부(시세 없는 종목) |
| `GET /sectors/{id}/etfs` | `marketCountry` | `etfs[]{symbol, name}` 하위 섹터 미포함, 직전 분기 시총↓ | 없음 |

- 등락률은 **소수 비율**(0.0123 = 1.23 %). 2026-08-12 수수료율 사고 재발 방지: 도메인은 비율 그대로, 표 출력만 ×100.
- 금액은 US 도 **KRW 환산**이고 통화는 항목별 `currency`. 금액 nullable 은 전부 `*float64` 로 들고 간다 — 0 과 "집계 없음" 을 구분.
- 목록에 없는 `sectorId` 는 404 `sector-not-found`. 데이터 없는 랭킹 조합은 오류가 아니라 빈 배열.

## 구현·공유 레지스트리 커버리지 비교

| 신규 경로 | 기존 표면 | 판정 | 근거 |
| --- | --- | --- | --- |
| `/sectors` | WTS `sectors`(`/api/v1/tics/all`, 39 대분류 + 하위, 1d/1mo/3mo/1y) | **신규** | 분류 체계 자체가 다르다(TICS 정수 id vs 공식 문자열 id). 공식은 계층 전체를 평면 + parent 로 주고 등락률은 안 준다. 서로 대체 불가 |
| `/sectors/rankings` | WTS `market themes`(`/api/v1/tics/rankings`, 당일 등락만) · 보류 후보 `/api/v2/dashboard/wts/overview/tics/ranking` | **신규(우월)** | 6개 기간 × 2개 기준 × KR/US. WTS 후보는 body 계약을 못 뚫어 deferred 였으므로 **추적 중단, overrides 에 사유 기록** |
| `/sectors/{id}` | WTS `sector_detail`(overview·simple) | **신규** | id 체계 다름. 공식은 요약 + 6기간 등락률, WTS 는 뉴스·연관 업종까지. 둘 다 유지 |
| `/sectors/{id}/stocks` | WTS `sector_detail` 의 stocks 첫 페이지 | **신규(우월)** | 공식은 전체(페이징 없음)·시총 정렬·거래량/대금 포함 |
| `/sectors/{id}/etfs` | WTS `sector_detail` 의 etfs 첫 페이지 | **신규** | 공식은 심볼·이름만이지만 전체를 준다 |

| `expireDate` ≤ 오늘 + 1년 | `internal/orderintent/conditional.go` | **사전 검증 추가**. 서버도 거절하지만 왕복 전에 막는다 |

| `client_id` 예시 `tsck_live_…` | — | 예시만. 변경 없음 |

## 함정 — 스냅샷이 4주 동안 1.2.17 에 멈춰 있던 이유

`daily-monitor` 는 정상 작동했다. 1.2.24 스냅샷은 자동화 PR **#293** 에 10/5 부터 올라가 있었고,
모니터는 그 브랜치 기준으로 "변동 없음" 을 보고했다. PR 이 안 들어간 이유는 **`pnpm audit --audit-level high`** 가
`next` 16.3.4 의 critical(next/og RCE)·high(Image SSRF) 와 전이 의존성 4건(brace-expansion·source-map-js·
compression·sharp) 때문에 10/8 부터 모든 PR 의 `test-and-build` 를 떨어뜨렸기 때문이다. dependabot #294(next 16.3.8) 도
전이 의존성 때문에 같은 자리에서 실패했다.

교훈: **모니터가 "변동 없음" 이어도 `last_checked_at` 과 열린 자동화 PR 을 같이 본다.** 저장소 `main` 의 스냅샷
날짜가 2주 이상 묵었으면 PR 큐가 막힌 것이다. 해결은 #295(next 16.3.8 + `pnpm.overrides`).

같은 기간 `wts-monitor` 도 09-28·10-05 두 번 실패했다. 원인은 다르다 — 9/21 자동화 PR #277 의 브랜치에
`origin/main`(#287 카탈로그 갱신) 을 머지하다 `wts-endpoints.json` 충돌. #277 의 내용은 #287 에 이미 반영돼
있어(2026-09-28-wts.md) #277 을 닫아 다음 주간 실행이 새 브랜치를 만들게 했다.
