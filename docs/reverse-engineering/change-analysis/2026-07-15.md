# API 변경 분석 — 2026-07-15

## 개요

`docs/migration/openapi.latest.json` (8,964줄)이 이번 커밋(`ae0e0d0`, "ci(monitor): 분석/PR 역할 분리")에서 **신규 파일로 추가**되었다. `git log --follow`, `git log --oneline`로 확인한 결과 이 저장소(shallow clone, depth=1)에는 커밋이 이 1개뿐이라 이전 버전과의 라인 단위 diff는 만들 수 없다. 다만 같은 디렉터리의 `docs/migration/.openapi-snapshot.json`이 이미 `spec_version: "1.2.4"`, `spec_path_count: 27`, `updated_at/last_checked_at: 2026-07-15`로 기록되어 있어, **이번 커밋이 신규 모니터링 파이프라인의 최초 베이스라인 스냅샷**임을 알 수 있다. 즉, 이번 실행에서 감지된 "변경"은 이전 스펙 대비 필드 추가/삭제가 아니라 "공식 스펙 전체를 처음으로 저장소에 고정(pin)한 것"이다.

- OpenAPI 버전: `3.1.0`
- API 제목/버전: `토스증권 Open API` v`1.2.4`
- 총 경로 수: 27개 (`/api/v1/*` 26개 + `/oauth2/token` 1개)

### MCP 툴 노출 범위 (`internal/mcp/operations.go`, `writes.go`)

MCP 툴 카탈로그는 공식 API 27개 경로 중 **20개**(GET 17 + POST 3: place/cancel/modify order)만 노출한다. 다음은 `internal/official/`에는 구현되어 있지만 MCP 툴로는 노출되지 않는다:
- `conditional-orders` 전체 (조건부 주문 조회/생성/취소/수정)
- `market-indicators/*` (지수 시세/캔들/투자자 매매동향)
- `rankings`

이는 이번 스펙 변경과 무관한 기존 설계이며, 이번 커밋으로 인해 새로 생긴 gap이 아니다.

## 분류

**(a) no-op** — 이번 커밋은 신규/삭제 엔드포인트, 스키마 breaking change가 아니라 공식 스펙을 처음으로 저장소에 고정한 베이스라인이다. 대조 결과 `internal/official/`가 이미 스펙 전체(27/27 경로·메서드)를 구현하고 있어 즉시 코드 변경이 필요한 항목은 없다.

## 권장 후속 조치

1. 이번 스냅샷(`.openapi-snapshot.json`, spec_version 1.2.4)을 이후 비교 기준선으로 사용한다. 다음 실행부터는 이 커밋과의 실제 diff(엔드포인트 추가/삭제, 스키마 변경)를 근거로 분류할 수 있다.
2. (선택, 이번 변경과 무관한 별도 개선 후보) MCP 툴에 `conditional-orders`, `market-indicators/*`, `rankings`를 노출할지 검토 — 이미 `internal/official/`에 구현되어 있으므로 MCP 래퍼만 추가하면 됨.
3. 실계좌 데이터/라이브 API 호출 없이 레포 내 파일만으로 분석을 완료함 — 별도 조치 불필요.
