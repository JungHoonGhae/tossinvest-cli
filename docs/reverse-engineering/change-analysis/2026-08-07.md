# API 변경 분석 — 2026-08-07

## 1. 변경 요약

공식 Open API spec 스냅샷(`docs/migration/openapi.latest.json`)이 커밋
`7fd9486`(자동화 `docs(migration): openapi-snapshot 자동 갱신`)으로 갱신됐다.
`info.version` `1.2.9` → `1.2.13`. `paths`는 27→32개(순증 5), `components.schemas`는
67→83개(순증 16), 삭제된 경로·스키마는 없다(전부 additive). diff 상에서
`StockInfo`/`StockWarning`/`Trade`/`SellableQuantityResponse`/`UsAfterMarketSession`/
`UsDayMarketSession`/`/api/v1/stocks`/`/api/v1/rankings`/`/api/v1/sellable-quantity` 등이
추가·삭제로 표시되지만, 새 스키마가 알파벳 순으로 그 사이에 삽입되면서 생긴 **위치
이동일 뿐 내용은 동일**함을 정규화 해시(sha256) 비교로 확인했다.

### 신규 경로 5개 (전부 `/api/v1/stocks/{symbol}/*`, GET, KR 전용, tag `Stock Info`)

| 경로 | operationId | 설명 |
|---|---|---|
| `/api/v1/stocks/{symbol}/credit-trades` | `getStockCreditTrades` | 신용거래 동향(신용융자·신용대주 신규/상환/잔고, 일별) |
| `/api/v1/stocks/{symbol}/investor-trading` | `getStockInvestorTrading` | 투자자별 매매동향(개인/외국인/기관 세부 7분류/기타법인, 외국인 보유·CFD 잔고 포함) |
| `/api/v1/stocks/{symbol}/program-trades` | `getStockProgramTrades` | 프로그램매매 동향(차익·비차익) |
| `/api/v1/stocks/{symbol}/securities-lending` | `getStockSecuritiesLending` | 대차거래 동향(기관 간 대차 체결/상환/잔고) |
| `/api/v1/stocks/{symbol}/short-selling` | `getStockShortSelling` | 공매도 동향(거래량·거래대금·비중) |

5개 모두 파라미터(`KrSymbol` path param, `count`/`until` query — cursor 페이지네이션,
응답의 `nextUntil`을 다음 요청 `until`로 전달), 응답 코드(200/400/401/403/404/429/500)
구조가 동일하다. Rate limit group은 전부 `STOCK_TRADING_TREND`(신규 그룹으로 보임,
기존 문서에 없던 이름). `KrSymbol` 파라미터와 `InternalErrorTradingTrend` 500 에러
컴포넌트도 이번에 신규 추가됐다.

`investor-trading`은 이름이 같은 기존 엔드포인트
`GET /api/v1/market-indicators/{symbol}/investor-trading`(`operationId`
불명, 이미 구현됨)과 **다른 데이터**다. 신규 엔드포인트의 `foreigner`는 "등록외국인"만
집계하는 반면 기존 market-indicators 쪽 `foreigner`는 등록·미등록 합계라고 스키마
설명에 명시돼 있다 — 이름이 겹쳐 혼동 소지가 있다.

데이터 적시성 관련 특기사항(각 레코드에 `null` 허용 필드로 반영): 기관·개인·기타법인
잠정치는 당일 저녁 확정 반영, 외국인 보유는 당일 저녁(익영업일 오전 확정), CFD 잔고는
T+1, 신용거래는 T+1(익영업일 새벽).

## 2. tossctl 커버리지 대조

`internal/official/`, `internal/mcp/`, `internal/ops/` 전체를 5개 operationId와
관련 타입/경로 문자열(`CreditTrades`, `ProgramTrades`, `SecuritiesLending`,
`ShortSelling`, `credit-trades`, `program-trades`, `securities-lending`,
`short-selling`)로 검색한 결과 **Go 소스 어디에도 매치 없음** —
`docs/migration/openapi.latest.json` 자체 외에는 참조가 전혀 없다. 5개 전부
미구현(client/CLI/MCP 모두).

참고할 기존 패턴 — `GET /api/v1/market-indicators/{symbol}/investor-trading`:

- Go 클라이언트: `internal/official/market_reads.go:508-525`
  (`(c *Client) MarketInvestorTrading(ctx, symbol, interval string, count int, until string)`),
  비공개 `apiInvestorTrading*` 구조체(484-505)로 원본 응답을 언마샬하고
  `adaptInvestorTrading`(537)로 도메인 타입 변환.
- 도메인 타입: `internal/domain/models.go:858-880`
  (`InvestorTradingParty`, `InvestorTradingRecord`, `InvestorTrading`).
- CLI: `cmd/tossctl/market.go:463-477` — `investor-trading <symbol>` 서브커맨드.
- 출력: `internal/output/marketdata.go`.
- **MCP는 이 기존 엔드포인트조차 연결 안 돼 있음.** `internal/ops/read_operations.go`에
  `MarketInvestorTrading` 항목이 없다 — 오늘 기준 CLI 전용.

코드 생성 도구는 없다. `Makefile`에 `generate` 타겟 없고, `openapi.latest.json`을 읽어
클라이언트 코드를 만드는 스크립트도 없음 — `internal/official/`은 전부 수기 작성이라
5개 신규 엔드포인트는 사람(또는 에이전트)이 직접 클라이언트 메서드 + 도메인 타입 +
`read_operations.go` 등록 + CLI 서브커맨드를 추가해야 반영된다.

## 3. 분류

**(b) 신규 기능 후보.** 삭제·변경된 경로·스키마가 없어 breaking 위험은 없다. 5개
신규 엔드포인트는 전부 조회 전용(GET)이고 기존에 구현된
`/api/v1/stocks/{symbol}/warnings`(`internal/official/warnings_reads.go` 추정)와
매우 유사한 모양(KR 종목 심볼 path param + 페이지네이션)이라, 그 파일을 템플릿 삼아
빠르게 이식 가능한 구조다.

## 4. 권장 후속 조치

1. `internal/official/`에 신규 파일(예: `stock_trading_trend_reads.go`) 또는
   `stock_reads.go` 확장으로 5개 클라이언트 메서드 + 도메인 타입 추가. 5개가 응답
   포맷(`records[]` + `nextUntil`)이 동일하므로 공통 헬퍼(제네릭 페이지네이션 파서)를
   먼저 만들면 중복을 줄일 수 있다.
2. `internal/ops/read_operations.go`에 5개 오퍼레이션 등록 — MCP로 노출.
   등록 시 기존 `market-indicators/investor-trading`도 함께 등록해 두면(현재 누락 상태)
   좋다. 다만 이름이 겹치는 두 `investor-trading` 엔드포인트를 MCP 오퍼레이션 이름/설명에서
   명확히 구분해야 한다(등록외국인 전용 vs 등록+미등록 합계).
3. `cmd/tossctl/`에 대응 서브커맨드 5개 추가 (예: `stocks credit-trades`,
   `stocks investor-trading`, `stocks program-trades`, `stocks securities-lending`,
   `stocks short-selling`), `--until` 커서로 페이지네이션 지원.
4. 실계좌 없이도 시세성 조회이므로 개발용 client credentials로 라이브 프로브 가능해
   보인다(계좌 스코프 헤더 불필요, `security: oauth2ClientCredentials`만 요구) —
   구현 전에 실제 응답 1건씩 확인해 스키마와 어긋나는 부분(예: null 필드 실제 발생
   시점)이 없는지 검증 권장.
5. `investor-trading` 이름 중복은 사용자 대면 문서(README/CLI help)에서도
   두 엔드포인트를 명확히 구분하는 문구가 필요 — 신규 커맨드 이름을
   `stocks investor-trading`처럼 상위 리소스를 붙여 기존 `market investor-trading`과
   구분하는 방안을 사람이 결정.
