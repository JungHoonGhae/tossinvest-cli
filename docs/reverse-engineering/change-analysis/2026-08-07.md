### 신규 경로 5개 — 전부 국내 종목 수급

```
GET /api/v1/stocks/{symbol}/investor-trading     투자자별 매매동향
GET /api/v1/stocks/{symbol}/short-selling        공매도 동향
GET /api/v1/stocks/{symbol}/credit-trades        신용거래 동향
GET /api/v1/stocks/{symbol}/securities-lending   대차거래 동향
GET /api/v1/stocks/{symbol}/program-trades       프로그램매매 동향
```

**다섯 개가 모양이 같다.** 파라미터는 `symbol`(path) · `count`(query, 기본 10) ·
`until`(query, 커서)이고, 응답은 `{nextUntil, records[]}` 의 일별 시계열이다. 금액·수량은
**문자열**로 온다(정밀도 보존).

신규 스키마 17개는 전부 이 다섯 응답의 부품이다:
`StockInvestorTradingResponse`/`Record`, `StockInstitutionTradingVolume`/`Breakdown`,
`InvestorTradingVolume`, `ForeignerHolding`, `CfdBalance`, `ShortSellingResponse`/`Record`,
`CreditTradesResponse`/`Record`/`Detail`, `SecuritiesLendingResponse`/`Record`,
`ProgramTradesResponse`/`Record`, `ProgramTradingVolume`.

## 4. 권장 후속 조치

1. `internal/official` 에 5개 read 추가 — 모양이 같으므로 **공통 시계열 헬퍼 하나**로
   묶고 레코드 파싱만 분기한다. 다섯 벌 복붙은 하지 않는다.
2. `quote flows` 를 하이브리드로 — 공식 `investor-trading` 우선, WTS 폴백. 필드가 늘어나므로
   `domain.TradingFlow` 확장이 따라온다.
3. 나머지 4개 노출 방식은 결정 필요(5절).
4. 카탈로그 `overrides` 갱신 — WTS 후보 4건을 "공식이 대체" 로.

## 5. 미결 — 노출 방식

네 개(공매도·신용·대차·프로그램)를 어떻게 낼지는 UX 결정이라 여기서 정하지 않는다.

| 안 | 형태 | 장점 | 단점 |
|---|---|---|---|
| A | `quote short-selling`, `quote credit-trades`, … 4개 커맨드 | 이름이 곧 기능, 탭 완성이 쉬움 | `quote` 하위가 15개로 늘어남 |
| B | `quote supply <symbol> --type short\|credit\|lending\|program` | `quote` 표면이 안 늘어남, 응답 모양이 같아 자연스러움 | `--type` 어휘를 외워야 함 |

응답 구조가 다섯 개 모두 동일하다는 점은 B 를 지지하고, 발견 가능성은 A 를 지지한다.

### 스펙을 얕게 읽어 한 번 틀렸다

`StockInstitutionTradingBreakdown` 의 7개 필드를 문자열 스칼라로 읽고 구현했다가
런타임에 깨졌다. 실제로는 `allOf → InvestorTradingVolume`, 즉 **각 분류가 매수/매도/
순매수 삼중**이다. 스펙 덤프에서 `allOf` 를 펼치지 않으면 타입이 `None` 으로 보이는데,
그걸 스칼라로 오해했다.

**`allOf` 로 감싼 `$ref` 는 덤프 스크립트가 놓치기 쉽다** — 다음 분석 때 `properties`
순회에서 `$ref`/`items.$ref` 뿐 아니라 `allOf[].$ref` 도 펼칠 것.

### nullable 이 실제로 값을 한다

라이브 확인에서 당일(2026-08-07) 잠정 기록의 개인·기타법인이 `-` 로 나왔다. 포인터로
안 들고 갔으면 "개인 순매수 0" 으로 보였을 것이고, 이는 정반대 신호다.

`quote flows` 는 `domain.TradingFlow` 가 평범한 float 라 이 구분을 잃는다. 출력 형식을
바꾸지 않기로 한 대가이며, 구분이 필요하면 `quote supply --type investor` 로 간다.
