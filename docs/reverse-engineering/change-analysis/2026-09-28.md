## 요약

**분류: (a) no-op — 현재 tossctl 구현 기준으로 문서 정정이며 구현 변경은 필요하지 않다.**

대상 커밋 `e9ca1db3557f3166860bba7a3505412f19762930`과 부모 `08c22270604823cb803cda01a558a1ea01932ac2`를 `tools/openapi_diff.py --rev e9ca1db3557f3166860bba7a3505412f19762930`으로 비교했다. OpenAPI 원문 텍스트 diff는 사용하지 않았다.

- 버전은 `1.2.17 → 1.2.19`. 경로는 33개, 스키마는 90개로 각각 추가·삭제가 없다.
- 전체 구조적 변경은 스칼라 경로 16개다. 버전 1개, 조건주문 수정 오퍼레이션 설명 1개, OAuth 400 응답 설명·예시 14개다. `components` 전체는 동일하며 요청·응답 스키마, 필수 필드, enum 변경은 없다.
- 조건주문 수정 설명에서 수량을 각 조건 내부에 넣으라는 잘못된 안내를 제거하고, 기존 스키마대로 최상위 `quantity`·`orderType`을 명시했다. 등록과 달리 수정에만 만료일이 필수라는 문구도 제거했다. 기존 생성·수정 스키마는 모두 `expireDate`가 필수다.
- OAuth 오류 예시는 요청 형식 문제를 세분화하고 `error_description`의 파라미터 이름을 설명한다. HTTP 400 요청 오류와 HTTP 401 자격증명 오류를 구별하라는 안내가 추가됐다.

AsyncAPI는 해당 커밋의 변경 파일 목록에 없으며, 부모·대상 커밋 모두 blob이 `cfdfff7d78438ff39d1cbea44c11e327ed514979`로 동일하다. 따라서 별도 AsyncAPI diff 대상은 없다.

## 구현·공유 레지스트리 커버리지 비교

신규 endpoint가 없으므로 신규 구현·레지스트리 등록 후보는 없다. 삭제 endpoint 및 삭제 스키마도 없다. 변경된 기존 endpoint의 구현은 다음과 같다.

## 분류 근거

**(a) no-op**으로 분류한다. 설명의 의미는 정정됐지만, 부모 스냅샷부터 요청 스키마가 이미 공통 수량·호가유형과 필수 만료일을 정의했고 현재 구현도 이에 맞는다. OAuth 변경 역시 오류 설명·예시 보완이며 스키마 또는 인증 방식 변경이 아니다. 새 기능이나 이번 변경으로 인한 구현 호환성 위험을 확인하지 못했다.

조건주문 수정 후 새 ID가 발급된다는 설명은 양쪽 스냅샷에 동일하게 존재한다. 이를 이번 커밋의 신규 동작 변경으로 계산하지 않는다. 이 판정은 이번 변경분에 대한 것으로 기존 구현 전체의 계약 준수를 보증하거나 실제 서버 동작을 관측한 결과는 아니다.

## 미분류 경로 전수 검토

도구 마지막 `[미분류 변경]`에 표시된 14개 경로의 양쪽 전체 값을 읽었다. 아래 표에서 `R`은 `paths./oauth2/token.post.responses.400`, `E`는 `R.content.application/json.examples`를 뜻한다. 표의 각 행은 실제 미분류 경로 하나에 대응한다.

| 경로 | 확인한 변경 및 분류 |
| --- | --- |
| `E.invalidRequest.summary` | 일반적인 필수 파라미터 누락·형식 오류 예시 제목 삭제. 상세 예시로 대체하는 문서 정리. |
| `E.invalidRequest.value.error` | 해당 예시의 `invalid_request` 삭제. 오류 코드 자체의 폐지는 아니며 새 예시에서 유지된다. |
| `E.invalidRequest.value.error_description` | `Required parameter is missing.` 예시 삭제. 문서 정리. |
| `E.malformedCredentials.summary` | Basic 헤더 형식 오류·자격증명 파라미터 중복 예시 추가. |
| `E.malformedCredentials.value.error` | 새 예시의 오류 코드는 기존 `invalid_request`. |
| `E.malformedCredentials.value.error_description` | Authorization 헤더 또는 `client_id/client_secret/code_verifier` 파라미터 점검 안내 추가. 이 예시만으로 새 grant나 PKCE 지원을 의미하지 않는다. |
| `E.missingClientSecret.summary` | 빈 문자열을 포함한 `client_secret` 누락 예시 추가. |
| `E.missingClientSecret.value.error` | 새 예시의 오류 코드는 `invalid_request`. |
| `E.missingClientSecret.value.error_description` | `OAuth 2.0 Parameter: client_secret` 예시 추가. |
| `E.missingGrantType.summary` | form-urlencoded가 아닌 요청을 포함한 `grant_type` 누락 예시 추가. |
| `E.missingGrantType.value.error` | 새 예시의 오류 코드는 `invalid_request`. |
| `E.missingGrantType.value.error_description` | `OAuth 2.0 Parameter: grant_type` 예시 추가. |
| `E.unsupportedGrantType.value.error_description` | `Only client_credentials grant type is supported.`에서 `OAuth 2.0 Parameter: grant_type`으로 예시 문구 변경. grant 지원 범위 변경은 아니다. |
| `R.description` | 필수 파라미터·형식 오류를 구체화하고 `OAuth 2.0 Parameter: {name}` 의미 및 401 `invalid_client`와의 차이를 설명한다. 400에서는 자격증명 값을 다시 복사하기 전에 본문·헤더를 확인하도록 안내한다. |

위 14개는 모두 오류 설명·예시 보완으로 분류했다. 도구의 `flatten`으로 전체 스냅샷을 구조적으로 비교한 변경 집합이 **버전 1개 + 조건주문 설명 1개 + 표의 14개**와 정확히 같음을 메모리 내 assertion으로 확인했다. `components` 전체 동일성도 검증했다. **최종 수동 검토 잔여 [미분류 변경]: 없음(0건).** 원본 도구의 미분류 출력이나 도구 코드를 변경하지 않았다.

## 권장 후속 조치

1. 이번 스냅샷에 따른 구현·ops 등록 변경은 하지 않아도 된다. 조건주문 수량·호가유형은 계속 최상위에 두고 생성·수정의 만료일 필수 규칙을 유지한다.
2. 인증 문제 안내를 향후 보완할 때 HTTP 400 요청 형식 오류와 401 자격증명 오류를 구별한다. `error_description`의 정확한 문자열을 프로그램 분기 조건으로 사용하지 않는다.
3. 인증 회귀 테스트를 추가하는 별도 작업이 있다면 새 400 예시를 합성 fixture로 사용해 `APIError` 본문 보존과 fallback 차단을 확인한다. 이번 문서 정정만으로 라이브 API 검증이나 주문 실행은 필요하지 않다.

## 실행 범위와 제한

보고서 한 파일만 작성했다. 커밋·push, 실서비스 API 요청, 실제 계좌 데이터 접근은 하지 않았다. 구현 변경이 없어 테스트 스위트는 실행하지 않았고, 로컬 스냅샷 구조 비교와 구현·기존 테스트 소스 확인으로 검증했다.

최초 도구 실행과 커밋 통계 조회에서 부분 클론의 부모 객체가 없어 Git이 GitHub 자동 fetch를 시도했으나 DNS 오류로 실패했다. **이는 GitHub 호출 금지 조건을 벗어난 실행상 이탈이다.** 이후 자동 fetch를 차단하고, `GIT_NO_LAZY_FETCH=1`, `protocol.allow=never`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`를 통해 기존 로컬 저장소의 객체를 읽어 지정 도구 실행과 분석을 완료했다. Git 설정이나 객체 파일은 직접 변경하지 않았다.
