# API 변경 분석 — 2026-10-28

## 요약

대상 커밋: `f304d0a42ee629f92de0e12f59faab59da2b0cb1`.
분석은 **미완료**다. 부모 스냅샷 객체가 로컬에 없어 변경 전체를 검증할 수 없다. 따라서 no-op 또는 신규 기능이라고 확정하지 않고 **(c) breaking risk — 잠정 분류**로 남긴다. 이는 호환성 파손을 확인했다는 뜻이 아니라, 파손 가능성을 배제할 비교 근거가 부족하다는 뜻이다.

커밋의 트리 메타데이터로 확인한 변경 파일은 `docs/migration/.openapi-snapshot.json`과 `docs/migration/openapi.latest.json`뿐이다. `docs/migration/asyncapi.latest.json`은 변경되지 않았으므로 해당 커밋의 AsyncAPI 본문 차분 검사 대상은 없다. 원문 텍스트 diff는 사용하지 않았다.

## 구조화 차분 실행과 미분류 변경

요청대로 다음 명령을 실행했다.

```sh
python3 tools/openapi_diff.py --rev f304d0a42ee629f92de0e12f59faab59da2b0cb1
```

새 스냅샷은 읽었지만 부모의 `docs/migration/openapi.latest.json`을 읽는 단계에서 실패했다. 누락된 부모 blob은 `17f432bb48a9377649f46d583e9cd8b6f014a629`다. 첫 실행에서는 partial clone의 Git이 GitHub promisor remote에서 객체를 자동 취득하려다 DNS 오류로 실패했다. 이 과정에서 의도하지 않은 GitHub 접근 시도가 있었다. 이후에는 `GIT_NO_LAZY_FETCH=1`로 자동 취득을 차단하고 같은 명령을 재실행했으며, `fatal: bad object`로 종료됐다. 라이브 API 요청은 하지 않았다.

**최종 `[미분류 변경]` 절은 생성되지 않았다. 잔여 0건을 확인하지 못했으므로 분석 완료 조건을 충족하지 않는다.** 이전 보고서의 잔여 0건을 이번 커밋의 검증 결과로 대체하지 않았다.

대상 커밋의 새 JSON을 직접 파싱한 결과 버전은 `1.2.24`, 경로는 38개, 스키마는 101개다. 부모와의 증감·삭제·필드 변경은 확인할 수 없다.

## 구현·공유 레지스트리 커버리지 비교

신규 endpoint 목록 자체를 추출하지 못했으므로 신규 경로의 전체 커버리지 및 삭제·변경 구현의 전체 영향 목록은 확정할 수 없다. 다만 저장소의 기존 `2026-10-28.md`가 언급한 조건주문 수정 경로를 대상으로 현재 구현과 새 스냅샷을 대조했다. 기존 보고서는 다른 커밋(`09a48baa`)을 분석했으므로 이번 커밋의 변경 증거로 취급하지 않았다.

| 확인 대상 | 새 스냅샷 및 현재 구현 | 판단 |
| --- | --- | --- |
| `POST /api/v1/conditional-orders/{conditionalOrderId}/modify` | 새 스냅샷에 존재. `internal/official/conditional_writes.go`의 `ModifyConditionalOrder`가 같은 경로를 호출하고 응답의 새 `conditionalOrderId`를 반환 | 기존 구현 있음. 이번 커밋에서 신규·변경됐는지는 미확인 |
| 수정 가능 상태·거절 | 새 설명은 `WATCHING`·`PAUSED`만 수정 가능하고 그 외 명시 상태 및 판정 중에는 `422 modify-restricted` 가능하다고 설명. `internal/hybrid/client.go`는 해당 오류에 상태 확인과 별도 주문 취소 안내를 추가 | 관련 구현 있음. 실행 검증은 하지 않음 |
| 공유 ops 등록 | `internal/ops/write_operations.go`의 `modify_conditional_order`가 동일한 POST 경로를 등록하고 수정 가능 상태·새 ID 반환을 설명 | 공식 클라이언트와 공유 레지스트리 연결 확인 |
| 취소·재생성 의미 | 스냅샷은 수정 시 기존 ID 무효화, 취소 시 이미 접수된 주문은 유지된다고 명시 | 조건주문 수정·취소 이용 흐름에 영향. 변경 시점은 미확인 |

## 분류

**(c) breaking risk, 잠정·검증 보류.** 확인한 조건주문 동작은 기존 코드에 대응이 있지만 이것만으로 커밋 전체를 no-op으로 판단할 수 없다. 신규 기능 후보, 삭제 endpoint, 타입·필수값·의미 변경 및 최종 미분류 경로는 부모 스냅샷 확보 후 판정해야 한다.

## 권장 후속 조치

1. 별도로 허용된 환경에서 부모 스냅샷 blob을 확보한 뒤 네트워크 자동 취득을 차단한 상태로 지정 `--rev` 명령을 다시 실행한다.
2. 모든 신규 경로를 `internal/official/` 및 `internal/ops/`에 대조하고 삭제·변경 항목의 호출부와 데이터 처리를 확인한다.
3. 최종 `[미분류 변경]`의 모든 경로를 개별 검토해 잔여 항목이 없음을 확인한 후 최종 분류를 갱신한다. 검토할 변경이 확정되면 영향에 맞는 로컬 테스트를 선택한다.

실계좌 데이터는 포함하지 않았다. 이 작업에서는 구현 수정·커밋·푸시를 하지 않았다.
